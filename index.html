04 How It's Built

How the modules behave

The same rules apply across modules: show the reasoning behind each score, ask before changing a host, and keep a way to undo changes where the platform allows. None of this replaces your own judgment or your organization's procedures.

Offline-first

Most modules never touch the network. Enrichment through VirusTotal, AbuseIPDB, Hybrid Analysis, or SerpAPI uses your own API keys, stored in the operating system's keyring.

Explainable

Scores list the rules that produced them: rule-level rationale for processes, a severity and MITRE ATT&CK technique for each email finding, and evidence tiers for AI Analysis. A score summarizes those rules; it is not a verdict.

Read-only by default

Analysis modules read and report. Anything that changes a host asks for confirmation in the window and requires --yes in the console.

Reversible

Secure Host snapshots the firewall configuration before isolating a machine. Startup Manager changes can be undone, and Malware Scan quarantines or disables items rather than deleting them. Where a restore is best-effort, as with Secure Host on macOS, the catalog says so.

Hash-checked

USB ISO Burner checks the image against a checksum you supply before writing and reads the drive back afterward. Triage kits write a SHA-256 manifest, and updates are checked against a SHA-256 hash before they are applied.

Cross-platform

Windows, macOS, and Linux, though several forensic modules read Windows-only artifacts. Each catalog entry states its platform limits.

Free tools such as Sysinternals Autoruns, CyberChef, Hayabusa, Nmap, and Rufus cover much of the same ground. What Nadirion adds is one interface and console for all of it, scores that show their rules, offline operation, and changes that can be undone. See the overlap, module by module.
